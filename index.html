Year 7 Digital Technologies

From plan to program

Today you practise turning pseudocode into Python, testing it and fixing errors. On Thursday you use these skills to build your own program in Thonny.

Your design brief: a helpful text program for new GIS pupils. It can be a quiz, a phrase translator or an info-bot.

By the end of this hour

1I can match each line of Python to its pseudocode and flowchart.
2I can test a program by trying different inputs.
3I can complete and order code using pseudocode as my guide.
4I can read an error message and fix the bug.

Teacher notes: start (3 min)

Read the four goals aloud. If students use the voice, they need headphones; otherwise leave Read aloud off and let them press the speaker button on each part.

Hour plan: Part 1 (8 min), Part 2 (10), Part 3 (10), Part 4 (10), Part 5 (15), wrap-up (4). Fast finishers can go back to Part 2 and find the replies they missed.

Teacher notes: Part 1 (8 min)

Goal: one pseudocode line becomes one Python line. Ask: "Which Python line matches ELSE IF?" and "Pseudocode has END IF. Where is that in Python?" (Python uses indentation instead.)

The "something else" topic sends the program down the ELSE path. Students tick this part off after following two different topics to the end.

Teacher notes: Part 2 (10 min)

This is testing: trying inputs on purpose to reach every branch. It is exactly what students do with their users in Week 11.

  • Quiz: "vientiane" in lower case is marked wrong. Ask why, and how a user would feel.
  • Library: typing "two" instead of 2 crashes with ValueError. Ask what int() needs.
  • Lao phrases: "Hello" with a capital H is not recognised.

    Teacher notes: Part 5 (15 min) and wrap-up (4 min)

    1. Missing colon after the if line (SyntaxError: expected ':').
    2. = instead of == in the if (SyntaxError: invalid syntax).
    3. The print under if is not indented (IndentationError).
    4. Typo: nmae instead of name (NameError).
    5. input() gives text, so wrap it in int() (TypeError).

    Do Bug 1 together on the board first: read the line number, then the message. Write the five error names on the board as the help-desk board for Thursday.

    Wrap-up: "Which error message helped you most, and why?" Then tell them Thursday they build their own program in Thonny from their pseudocode, saving a new version after each milestone.
