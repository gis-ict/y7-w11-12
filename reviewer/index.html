Thinking like a computer scientist

Week 2

Before you code, you think. Break a big problem into small parts, look for patterns, keep only what matters, then write the steps.

DecompositionBreaking a big problem into smaller parts.
Pattern recognitionSpotting what is the same or repeats.
AbstractionKeeping the important details and hiding the rest.
AlgorithmStep-by-step instructions to solve a problem.

Real world

  • Decomposition: a food delivery app splits one job into small jobs: choose a restaurant, order, pay, cook, deliver.
  • Pattern recognition: a mini mart notices the queue is always longest at lunch time, so it opens a second till.
  • Abstraction: a map app shows roads and places, not every tree and house.
  • Algorithm: a recipe for sticky rice: soak, drain, steam, serve.

Watch out

  • Requirements come from the users, so you ask them (a survey). Don't guess what people want.

Check yourself

Planning a class party: "food, music, games, invitations". Which skill is this?
Decomposition: one big job broken into smaller parts.
A school bus map shows only the stops. Which skill is that?
Abstraction: it keeps what you need and hides the rest.

Flowcharts and pseudocode

Week 3

The same algorithm can be drawn as a flowchart or written as pseudocode. Both are plans you make before you code.

ShapeMeansExample
OvalStart or EndStart
ParallelogramInput or OutputINPUT name
RectangleProcess (do something)total = a + b
DiamondDecision (Yes or No)Is age ≥ 12?
ArrowWhich way to go next→
PseudocodePlan written in simple English-like steps: INPUT, OUTPUT, IF, THEN, ELSE, END IF.
Control structuresSequence (in order), selection (choose), iteration (repeat).
TraceFollow the steps one at a time to predict what happens.
Trace tableA table showing each variable's value after each step.
INPUT age
IF age >= 12 THEN
    OUTPUT "You can join"
ELSE
    OUTPUT "Not yet"
END IF

Real world

  • An ATM is a flowchart in real life: input your card and PIN, then a diamond asks "PIN correct?". Yes leads to your money, No leads to "Try again".

Watch out

  • A diamond always has two ways out: Yes and No. Label both.
  • Input and output use the parallelogram, not the rectangle.

Check yourself

Which flowchart shape asks a question?
The diamond (a decision).
Trace the pseudocode above with age = 10. What is the output?
"Not yet"
Name the three control structures.
Sequence, selection and iteration.

Hello, Thonny: print, strings and comments

Week 4

Python runs your lines from top to bottom, in order. print() shows something on the screen.

EditorThe top part of Thonny, where you write and save your program.
ShellThe bottom part, where Python shows the output and errors.
StringText inside quotes: "Sabaidee"
CommentA note starting with #. Python skips it.
# My first program
print("Hello, Year 7!")
print("Sabaidee from my computer")
print("2 + 3")    # shows 2 + 3
print(2 + 3)      # shows 5

Remember

  • Quotes make it text, so print("2 + 3") shows 2 + 3 and doesn't do the maths.
  • Order matters. In ASCII art, the order of your print lines is the picture.
  • Save with the class pattern: Y7_Surname_ProjectName.py
  • Errors are information, not failure. Read the red text.

Real world

  • Comments are like sticky notes on a recipe: "use less chilli". The cook reads them, but they are not part of the food.
  • A shop receipt printer works like print(): line by line, top to bottom.

Watch out

  • Print("Hi") with a capital P fails. Python is case-sensitive.
  • Every opening quote and bracket needs a closing one.

Check yourself

Where does the output appear in Thonny?
In the shell (the bottom part).
What does print("5" + "5") show?
55 (it joins the two strings).

Variables, input() and f-strings

Week 5

A variable is a named box (envelope) that stores a value. input() asks the user and stores what they type.

name = input("What is your name? ")
food = input("Favourite food? ")
print(f"Hi {name}! I like {food} too.")
VariableA name that stores a value: name = "Mali"
=Means "store this in the box". It is not "equals" like in maths.
input()Asks a question and waits for the user to type.
f-stringf"...{name}..." puts a variable's value inside text.

Good variable names

  • Say what is inside: jump_distance, not x
  • No spaces (use _), can't start with a number, no symbols like ! or ?
  • score and Score are two different variables.

Real world

  • Your phone contacts: the label "Mum" is the variable name, and the phone number is the value.
  • "Hi Mali, your order is on the way" is an f-string. The app fills in your name.

Watch out

  • Forgetting the f prints the braces: print("Hi {name}") shows Hi {name}.
  • A new value replaces the old one in the box.

Check yourself

Which name is NOT allowed: rizz_level, 2nd_place, boba_count?
2nd_place, because a name can't start with a number.
x = 5 then x = 9. What is in x now?
9. The new value replaces the old one.

Numbers and data types

Week 6

input() always gives you text (a string). To do maths, change it into a number with int() or float().

TypeWhat it isExamples
intWhole number12, 0, -3
floatNumber with a decimal point4.5, 1.55
strText, in quotes"Soulisok", "67"
a = input("Number: ")        # user types 10
b = input("Number: ")        # user types 5
print(a + b)                   # 105  (text joined!)
print(int(a) + int(b))         # 15   (real maths)

total = 12 + 15 + 9
average = total / 3
print(f"Total: {total}, average: {average}")   # 36, 12.0

Remember

  • Maths operators: + add, - subtract, * multiply, / divide.
  • / always gives a float: 36 / 3 is 12.0
  • "67" is a string, but 67 is an int.

Real world

  • A phone number is stored as text, not a number. It can start with 0 and you never add phone numbers together.
  • In 1999 NASA lost the Mars Climate Orbiter because one team used different units from another. The numbers were the wrong kind for the program, and that cost about 125 million US dollars.

Watch out

  • int(input()) crashes with ValueError if the user types "two" instead of 2.
  • Comparing text with a number ("7" >= 5) gives TypeError.

Check yourself

What type is 4.5? And "4.5"?
4.5 is a float. "4.5" is a string, because it's in quotes.
Fix it so it adds: age = input("Age? ")
age = int(input("Age? "))

Selection: if, elif, else

Week 7

Selection lets a program choose. Python checks each condition from the top and runs only the first branch that is True.

temp = int(input("Temperature? "))
if temp >= 35:
    print("Very hot. Drink water!")
elif temp >= 25:
    print("Warm day.")
else:
    print("Cool day.")
OperatorMeansOperatorMeans
==equal to!=not equal to
>greater than<less than
>=greater or equal<=less or equal

Remember

  • if starts it, elif means "else if", and else catches everything left.
  • Every if, elif and else line ends with a colon :
  • The lines inside are indented with 4 spaces.
  • Order matters: put the most specific check first.
  • Each if is a diamond in the flowchart.

Real world

  • A game: if lives == 0, show "Game over"; else keep playing.
  • A vending machine: if money >= price, give the drink; else ask for more coins.

Watch out

  • = stores, == compares. if answer = "10": is a SyntaxError.
  • "Red" and "red" are not equal, because capitals matter.

Check yourself

In the code above, the user types 40. What prints?
"Very hot. Drink water!" Only the first true branch runs, even though 40 >= 25 is also true.
The user types 18. What prints?
"Cool day." (the else branch)
What is missing? if mood == "happy"
The colon at the end: if mood == "happy":

All term

An error message tells you which line and what went wrong. Read it, fix one thing, run again.

ErrorWhat it usually meansExample
SyntaxErrorPython can't read it: missing :, quote or bracket, or = instead of ==if x == 5
IndentationErrorA line inside an if isn't indentedif x:
print("hi")
NameErrorPython doesn't know that name: a typo or a missing variableprint(nmae)
TypeErrorMixing types that don't go together"7" >= 5
ValueErrorThe value can't be convertedint("two")
Syntax errorThe program won't run at all, because the code breaks Python's rules.
Logic errorIt runs, but gives the wrong answer. Only testing finds it.
BugA mistake in a program.
DebuggingFinding and fixing bugs.

Real world

  • In 1947, engineers working with Grace Hopper found a real moth stuck in their computer. They taped it into their logbook as the first actual "bug" found.
  • AI tools can write code that looks right but is wrong. Never trust code you can't trace.

Check yourself

print(f"Hi {nmae}"): which error?

The program runs but says 10 + 5 = 105. Syntax or logic error?

Digital footprint and account security

Week 9

Everything you do online leaves a trail that can last forever. Protect your accounts with strong passwords and more than one lock.

Digital footprintThe trail of data you leave online.
Active footprintWhat you choose to share: posts, comments, photos.
Passive footprintData collected without you posting: searches, location, cookies.
PermanenceDeleting is not forever. Screenshots, shares and archives keep it.
CookieA small file a website saves to remember what you do.
MFAMultifactor authentication: two or more different proofs to log in.
MFA proofMeansExample
Something you knowa secretpassword, PIN
Something you havean objectyour phone getting a code
Something you areyour bodyfingerprint, Face ID
PhishingA fake message pretending to be someone you trust, to steal your details.
Social engineeringTricking a person (not a computer) into giving information.
Brute forceA computer trying every combination until a password works.
Strong passwordLong and hard to guess. A passphrase of random words works well.
FirewallA barrier that blocks unwanted traffic from a network.
EncryptionScrambling data so only the right person can read it.

Real world

  • A deleted post can still exist as a screenshot on someone's phone. The Wayback Machine keeps old copies of websites from years ago.
  • You search for football boots and then see boot adverts everywhere. That's your passive footprint being used.
  • Using a bank card at an ATM is MFA: the card is something you have and the PIN is something you know.
  • "You won a free phone! Log in here" is a classic phishing message.

Home account check

  • Turn on MFA (2-step verification).
  • Use a different strong password for each account.
  • Check your privacy settings and turn off location where it isn't needed.
  • Look through your old posts. THINK before you post: is it True, Helpful, Inspiring, Necessary, Kind?

Watch out

  • A password plus a security question is not MFA. Both are things you know.
  • Fun quizzes asking for your pet's name and birthday may be collecting password clues.

Check yourself

Why does MFA protect you even if a hacker steals your password?
They still need the second proof, such as the code on your phone.
Fingerprint and password: which two types of proof?
Something you are (fingerprint) and something you know (password).
Is a website remembering your searches an active or a passive footprint?
Passive: it was collected without you posting anything.

Week 10

A design project starts with a brief and real users. You find out what they need, then plan the program as pseudocode and a flowchart before coding.

Design briefThe task you are given. Ours: a helpful text program for new GIS pupils (a quiz, a phrase translator or an info-bot).
PurposeWhy the program exists and who it helps.
RequirementsWhat the program must do, found by asking users.
SurveyQuestions you ask real users (we asked 3).
Competing considerationsTwo good things that pull against each other, so you must choose (a trade-off).
CriteriaThe checklist used to judge if the program is good.
MilestonesCheckpoints in your plan: design, build, test, finish.
Client / userThe person you build it for, and the people who use it.

Real world

  • An architect doesn't build until the family says what they need: how many rooms, the budget, and when it must be finished.
  • Trade-off example: more quiz questions teach more, but the quiz takes longer and users may get bored.

Build, test and evaluate

Weeks 11 to 12

Turn each pseudocode line into a Python line. Test every branch with different inputs, save versions, and judge your program against the criteria.

PseudocodePython

OUTPUT "Hi"print("Hi")

ImplementTurn your design into working code.
TestingTrying inputs on purpose to reach every branch, including unusual ones like "Lunch" or "two".
Version savingSave v1, v2, v3 so you can go back if something breaks.
EvaluateJudge the program against the criteria: what works, the trade-offs, what to do next.
Peer feedbackClassmates try it and tell you one strength and one thing to improve.
Comments in codeExplain each part with # notes using the right technical words.

Real world

  • Game companies let beta testers play early versions to find bugs before release.
  • Google Docs keeps a version history so you can go back to an older copy.
  • Judges in a cooking competition use a score sheet. That score sheet is their criteria.

Watch out

  • Testing only the "happy" input isn't enough. Test every branch, and test what users might really type.

4: one for each topic, and one to reach the else.

If the new feature breaks the program, you can go back to the working version.
